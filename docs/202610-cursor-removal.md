# cursor-agent を外した記録

2026 年 10 月、しばらく使う予定がなくなったので cursor-agent のエンジンを外した。
最後に cursor が入っていたコミットは `7ead9b7`。戻すときはそこから
エンジン本体、出力の記録とそれを流すテスト、ログインの手続き、Dockerfile の導入、
compose のボリュームを拾ってくる。

エンジンを選ぶ仕組み（`EngineId` とエンジンの一覧、ログインの手続きの表）は残してあり、
いまは Claude Code だけが載っている。cursor で作ったトピックはエンジンに `cursor` を
持ったままだが、知らないエンジンとして既定のモデルに落ちるので、開けば Claude Code で話す。
NAS に残っている cursor のボリューム（設定と認証）は compose から外しただけで、消してはいない。

以下は開発の手引きに書いてあった、cursor で実際に踏んだ落とし穴。戻すときにまた要る。

## 出力の読み方

`assistant` イベントは、道具を挟むと本文がいくつかの区切りに分かれ、区切りの終わりに、
そこまでの差分を丸ごと繰り返した言い直しが一つ届く。`timestamp_ms` が無いのは
いちばん最後の区切りだけで、途中の区切りの言い直しはキーも中身の並びも差分と
まったく同じ形で来る（`model_call_id` が付く回もあるが、付かない回もある）。
見分けずにつなぐと、道具を使った回だけ前半が二重になる。頼れるのは「それまで流した分と
丸ごと同じ」という形だけで、短い区切りではたまたま同じ差分とも区別が付かないため、
いったん預かって次の行で決めていた。`result` が持つのは最後の区切りだけなので、
本文は区切りをつないだ方を採る。

途中の様子（何を読んでいるか）は `tool_call` の `started` で分かる。道具の種類は
`readToolCall` のような `...ToolCall` で終わるキーの名前で表され、同じ器に
`toolCallId` や `startedAtMs` も混ざる。2026.08.11-e8db854 で実際に出たのは
read / glob / grep / webSearch / webFetch の五つ。

出力の確かめ方は、本物の出力を保存して中の絶対パスを均した記録を、記録をそのまま吐く
シェルスクリプトに読ませ、それを CLI の代わりに起動してエンジンを丸ごと通すやり方だった。

## 権限とウェブ

ヘッドレスでもウェブ検索とページ取得のたびに承認を求め、答える人がいないので即
`User Rejected` になる。検索は `cli-config.json` の `autoAcceptWebSearch` で通るので、
起動のたびに書き足していた（設定はボリュームの中なのでイメージには焼けない。
ログインし直すと CLI が書き直すことがあるので、ログインのあとにも書き直す）。
ページ取得を通す道は `--force` だけで、`permissions` の許可リストは `--print` の経路では
見ていない（2026.08.04-aaa8809 で確認）。`--force` を足しても ask モードなら書き込みと
シェルは道具ごと無いままで、増えるのはウェブの読み取りだけ。

人格の `AGENTS.md` は昔から親まで遡って読む。役割の指示は本文の先頭に積んでいた。

## 導入とログイン

公式の install スクリプトは版を選べない（取得した時点の最新が埋め込まれて降りてくる）。
CI から毎回叩くと版が勝手に上がってログインが切れるので、スクリプトがやっていること
（`downloads.cursor.com` から tar を展開して `~/.local/bin` に symlink）を Dockerfile に
写して版を固定していた。導入の層はビルド成果物と依存より上に置く。下に置くとコードや
依存を直すたびに入り直しになり、そのとき版が上がってログインが切れる。起動の速さは
版でかなり違い、init までが 2026.08.04-aaa8809 は 12〜13 秒、2026.09.23-86fc751 は 5 秒ほどだった。

認証の置き場所は二か所に分かれる。`~/.cursor` が設定と履歴で、トークン本体は
`~/.config/cursor/auth.json`。両方をボリュームにしないと作り直すたびに再ログインになる
（行き着くまでの経緯は `202608-cli-auth-persistence.md`）。ホームごと被せると
`~/.local/bin` の本体が隠れるので、置き場所だけを個別に渡す。

管理画面からのログインは、`NO_OPEN_BROWSER=1` を立てて `cursor-agent login` を起こすと
`https://cursor.com/loginDeepControl?…` を一行出し、認証が済むまで自分で問い合わせ続けて
終わる（2026.09.23-86fc751 で確認）。Claude Code と違ってコードを貼り返す必要はない。
状態は `status --format json` の `isAuthenticated` と `userInfo.email` で見る。
