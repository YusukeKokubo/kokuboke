# 覚え書き — MCP で開ける最初の道具

会話の中で知った家族の事実や好みを、AI 自身に覚えさせる。入口は MCP の道具一つ。
エンジンは今までどおり読み取り専用のまま（cursor は ask モード）にして、
「書く」だけをこちらが実装した道具に開ける。道具の中身はサーバーのコードなので、
書ける場所も量もそこで全部決まる。

ask モード + `--approve-mcps` で MCP の道具が呼ばれ、結果がエージェントに返ることは
2026.08.11-e8db854 で確認した。ただし macOS で。コンテナでの再確認は下の確認事項に。

## かたち

- 道具は `remember` 一つ。引数は覚える内容の文字列だけ。パスも宛先も受けない。
  書き先は起動時にサーバーが決めた一か所に固定する。引数を増やすとモデルが触れる
  範囲が引数の分だけ広がるので、最初から受け取らない。
- 書き先は `data/<user>/覚え書き.md`。日時を添えて追記するだけ。
- 読ませ方は profile.md と同じ。サーバーが読んで chatPrompt に差し込む。
  CLI に自力で読ませる案は捨てた。ask モードでも読みには行けるが、毎回読みに行く
  保証がない。差し込みなら必ず届く。
- 差し込みは `<profile>` に混ぜず `<memory>` の別枠にする。ファイルを分けても
  プロンプトで混ざれば、モデルからは人の書いた profile と切り分けられなくなる。
  枠の前置きに「あなたが前の会話で覚えたもの。間違いは人が直す」と出自を書く。
  唆されて覚えた行が、家族の書いた profile と同じ権威で効かないようにするため。
- 覚えた分が効くのは次の発言から。chatPrompt は CLI の起動前に組むので、
  その回の返答には乗らない。同じターンに効かせる仕掛けは作らない。覚えた内容は
  その回はモデル自身の文脈に既にあるので、差し込む必要がない。
- remember が書くのは、起動時に「個人スペースの会話」と確定しているときだけ。
  家族共有・summary や tags の経路・文脈が取れないときは追記を断って、
  その旨をモデルに返す。既定を断る側に置くので、mcp.json の置き場の都合で
  道具が余計な経路から見えても、書ける場所は増えない。
- MCP サーバーは stdio の行区切り JSON-RPC を自前で受ける小さい入口（`server/mcp/`）。
  実験では 70 行で足りた。SDK は捨てた。`dependencies` はサーバーが実行時に読むものだけ、
  という方針に対して、増える量が見合わない。
- システムプロンプトに「家族の事実や好みを知ったら remember で覚える」を一文足す。
  個人スペースだけ。

## 捨てた案

- 人格ファイル（`data/**/CLAUDE.md`）への直接追記。人が書いた人格と機械の追記が
  混ざって、変なことを覚えたときに切り分けて戻すのが面倒。別ファイルなら丸ごと消せる。
- エンジンのエージェントモードで直接書かせる。cursor の編集道具は `--force` 無しでも
  承認なしで通り、workspace の外への書き込みまで成功した（2026.08.11-e8db854）。
  パスを絞る仕掛けが無いので、書かせる＝コンテナから見える場所ぜんぶになる。
  そこには家族全員のトピックも CLI の認証も入っている。
- outbox（ファイル置き逃げ）。ask モードには Write そのものが無いので成立しない。
- 家族共有スペースから呼ばれたとき家族側の覚え書きに書いてしまう案。発言者が
  混ざるスペースでは「誰についての記憶か」の持ち方が決まっていないまま
  書き溜まるだけになる。断る方に倒す。

## 未決と確認事項

実装初日に叩いて決めた（2026.08.30）。

- 文脈は mcp.json の `env` に `${KOKUBOKE_REMEMBER_USER}` と書き、個人チャットの spawn だけその値を足す。cursor は mcp.json に書いたキーしか MCP の子へ渡さない。親 env を丸ごと継ぐことはない。cwd は workspace（トピックフォルダ）になるので、書く判定は env と cwd の両方を見る。
- mcp.json は global（`~/.cursor/mcp.json`）にマージする。起動ごとに書き換えない。既存の他サーバーは消さない。workspace 側（トピックの `.cursor/`）は git ルートまで遡られて、リポジトリ内では届かない。コンテナの `/data` は git では無いのでトピック直下でも届くが、global 一本の方が手元と揃う。
- コンテナ（Linux）でも ask + `--approve-mcps` のフラグがあり、stdio の行区切り JSON-RPC で MCP が ready になる。`${VAR}` 展開も同じ。

残しているもの:

- Claude Code への展開は後回し。`--allowed-tools Read` のままだと MCP の道具も塞がれる
  はず（未確認）。cursor で形が固まってから開け方を調べる。
- 家族共有スペースは対象外で始める。発言者が混ざるので「誰についての記憶か」の持ち方が
  決まっていない。個人側で回してから考える。

## 不安

- 覚え書きは毎回プロンプトに入るので、変なことを一度覚えると以後の会話ぜんぶに効く。
  cursor はウェブページを読むから、ページに唆されて覚える経路も残る。ファイルが data/ に
  あって人が消せること、上限があることが今の緩和で、防げるとは言えない。
- 上限を超えたときは追記を断って、道具がその旨をモデルに返す。整理は人がやる。
  溜まる速さが読めないので、上限はまず小さく（8KB くらい）始めて様子を見る。
- 消す・見る UI は範囲外。当面はファイルを直接編集する。
